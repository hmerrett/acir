# acir

Control a CostWay portable air conditioner over IR from a Raspberry Pi Pico W,
exposed to Home Assistant as a `climate` entity via MQTT.

The unit speaks **TCL112**. That was established by capturing the original
remote, not by guessing — see [Protocol](#protocol).

## Status

Working and in use. Tested with:

- Raspberry Pi Pico W (RP2040), MicroPython 1.29.0
- CostWay portable AC with a TCL-family remote (`23 CB 26` prefix)
- Home Assistant 2026.8.3, MQTT discovery, Mosquitto
- Broadlink RM Pro — capture only, not needed at runtime

## Hardware

A Pico GPIO sources ~12 mA. An IR LED wants 100 mA+ for useful range, so the
GPIO switches a transistor.

```
 VBUS (5V) ──[33Ω ½W]──▶|── IR LED ──┐
                                     │ collector
                                    ┌┴┐
 GP15 ──[330Ω]──── base ────────────┤ │ 2N2222A
                                    └┴┘
                                     │ emitter
                                    GND
```

| From | Via | To |
|---|---|---|
| VBUS (pin 40) | 33 Ω ½W | LED anode (long leg) |
| LED cathode | — | transistor collector |
| GP15 (pin 20) | 330 Ω | transistor base |
| emitter | — | GND (pin 38) |

Add **100 µF + 100 nF across the 5 V rail next to the LED**. Without it, 100 mA
pulses at 38 kHz ripple the rail enough to brown out the wifi chip, which
presents as random dropouts.

Optional, for capture: a TSOP38238 on GP16, with 100 Ω in its supply line.

Gotchas:

- VBUS only has 5 V when powered over USB. From VSYS, use 3V3 with 15 Ω.
- The IR receiver's middle pin is GND; the outer two vary by manufacturer.
- Boards sold as "RP2040 Pico W" with USB-C are clones using an ESP8285 on
  UART0, not a CYW43. MicroPython's `network.WLAN` cannot drive them.
- Don't use GP23/24/25/29 — wifi and power circuitry.

## Install

```
mpremote connect auto mip install umqtt.simple
cp src/secrets.example.py src/secrets.py   # then edit it
mpremote connect auto fs cp src/*.py :
mpremote connect auto reset
```

`main.py` runs at boot. ~10 s from reset to MQTT online. USB supplies power
only; all traffic is wifi, so a phone charger is fine.

**Any `mpremote` command stops the bridge** — it sends Ctrl-C to get a REPL and
doesn't restart `main.py`. Finish with `mpremote connect auto reset`.

## Use

From Home Assistant, the entity appears by itself via MQTT discovery. Directly:

```python
import ac
ac.on(temp=20, fan='high')
ac.set(mode='dry')
ac.off()
```

Topics are listed in [docs/INTEGRATION.md](docs/INTEGRATION.md).

## Protocol

TCL112: 112-bit frames, bytes LSB-first, prefix `23 CB 26`, checksum in byte 13.
Every press sends two blocks — a constant preamble (`MsgType 0x02`) then the
state (`0x01`) — separated by 69.9 ms.

| Field | Location |
|---|---|
| Power | byte 5 bit 2 |
| Econo | byte 5 bit 7 |
| Mode | byte 6 bits 0-3 — heat 1, dry 2, cool 3, fan 7, auto 8 |
| Turbo | byte 6 bit 6 |
| I Feel | byte 6 bit 7 |
| Temp | byte 7 bits 0-3, encoded as `31 - °C` |
| Fan | byte 8 bits 0-2 — auto 0, min 1, low 2, med 3, high 5 (4 unused) |
| SwingV | byte 8 bits 3-5 |
| Checksum | byte 13, `sum(bytes[0:13]) & 0xFF`, +0x0F when byte 3 is 0x02 |

Mapped by capturing 18 scenarios from the real remote and diffing them.
**Turbo is byte 6 bit 6, not bit 5** as IRremoteESP8266 documents — this unit
disagrees with the reference implementation.

Raw captures are in `captures/remote.json`.

## Tests

```
python3 tests/run.py
```

Runs the firmware under CPython with `machine` and `rp2` stubbed. Covers carrier
arithmetic, µs-to-carrier-period rounding, the capture state machine, and the
Coolix/Gree/Midea/TCL112 encoders. 14 frames captured from the real remote are
regression fixtures — if the encoder stops reproducing them, the tests fail.


## Notes

The 38 kHz carrier is generated by a PIO state machine; bit-banging it from
MicroPython has worse jitter than the pulse widths. Intervals are counted in
whole carrier periods (26.3 µs) so the state machine never divides — 1.25%
error on a 560 µs pulse, against the ±20% a receiver tolerates.

IR is one-way. Published state is what was last *sent*. Using the physical
remote desyncs it until the next command.
